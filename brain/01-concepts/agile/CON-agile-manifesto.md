# Agile Manifesto

## 4 Values

```
We value:

Individuals and interactions     OVER  processes and tools
Working software                 OVER  comprehensive documentation
Customer collaboration           OVER  contract negotiation
Responding to change             OVER  following a plan

(Right side still has value — left side valued more)
```

## 12 Principles (Summarized)

| # | Principle (Short) |
|---|------------------|
| 1 | Customer satisfaction through early and continuous delivery |
| 2 | Welcome changing requirements, even late in development |
| 3 | Deliver working software frequently (weeks, not months) |
| 4 | Business people and developers work together daily |
| 5 | Build projects around motivated individuals, trust them |
| 6 | Face-to-face conversation is the most effective communication |
| 7 | Working software is the primary measure of progress |
| 8 | Sustainable development pace — indefinitely maintainable |
| 9 | Continuous attention to technical excellence and good design |
| 10 | Simplicity — maximizing work not done — is essential |
| 11 | Best architectures emerge from self-organizing teams |
| 12 | Reflect and adjust regularly (retrospectives) |

## Common Misconceptions

| Misconception | Reality |
|--------------|---------|
| "Agile = no documentation" | Documentation still exists, just right-sized |
| "Agile = no planning" | Planning happens every sprint, just shorter horizon |
| "Agile = no process" | Scrum IS a process — Agile enables better process |
| "Agile = Scrum" | Scrum is one Agile framework; others exist (Kanban, SAFe, LeSS) |

## Agile Frameworks

- **Scrum** — sprints, fixed roles, ceremonies (most common)
- **Kanban** — continuous flow, WIP limits (great for ops/support)
- **SAFe** — Scaled Agile Framework (enterprise, 100+ people)
- **LeSS** — Large Scale Scrum
- **XP** — Extreme Programming (dev practices: TDD, pair programming, CI)
