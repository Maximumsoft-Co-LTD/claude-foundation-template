# OKR Framework

## Structure

```
Objective (O):   Qualitative, inspiring, memorable goal
  Key Result 1 (KR): Measurable outcome that proves O is achieved
  Key Result 2 (KR): ...
  Key Result 3 (KR): ...
```

**Rule:** Objectives are GOALS. Key Results are MEASURES. Never confuse with tasks.

## Example (Good vs Bad)

```
❌ Bad OKR:
  O: Improve the platform
  KR1: Release 10 features
  KR2: Write documentation
  KR3: Fix bugs

→ "Release 10 features" is OUTPUT (task), not OUTCOME (result)

✅ Good OKR:
  O: Become the most trusted payment platform for SMEs
  KR1: Monthly active merchants grow from 500 → 1,500
  KR2: Payment success rate increases from 94% → 99%
  KR3: Support ticket volume decreases by 40%
  KR4: NPS score reaches 60+

→ All KRs are measurable outcomes that prove O was achieved
```

## OKR Types

| Type | Scope | Cycle |
|------|-------|-------|
| Company OKRs | Entire organization | Annual |
| Department OKRs | Engineering, Product, Sales | Quarterly |
| Team OKRs | Scrum team, squad | Quarterly |
| Individual OKRs | Personal growth | Quarterly (optional) |

**Cascade:** Company → Department → Team (aligned, not copy-pasted)

## Scoring

```
0.0 - 0.3  → Failed to make progress
0.4 - 0.6  → Made progress but fell short
0.7 - 1.0  → Achieved

Target: 0.7 average = "stretched but achievable"
Always 1.0 = objectives were too easy
Always < 0.5 = objectives were too ambitious or bad execution
```

## OKR Calendar

```
Week 1 of Quarter:  OKR setting (team aligns with company OKRs)
Mid-quarter:        OKR check-in (track progress, adjust if needed)
End of quarter:     OKR review + score
Week 1 next quarter: New OKRs (informed by last quarter learnings)
```

## Common Mistakes

| Mistake | Fix |
|---------|-----|
| Too many OKRs (> 5) | Focus on 3-5 per level |
| KRs are tasks ("Launch feature X") | KRs are outcomes ("Active users grow by X%") |
| Set and forget | Check in monthly, update if context changes |
| No connection to strategy | Each O should connect to company/product vision |
| 100% top-down | Mix top-down direction with bottom-up team input |
