# Discovery

The phase before implementation where the team explores the problem space, validates assumptions, and defines what to build and why. Transforms vague ideas into clear, actionable user stories with acceptance criteria.

**In this template:** `/discovery` is a structured 10-topic command that must be run before any `/new-sprint`. It is the required first step of every sprint lifecycle.

**Key outputs:** User stories + AC, risk/spike list, scope boundaries, shared team understanding.

**Common pitfall:** Skipping discovery on "simple" features — see [[LES-003-discovery-skipped-caused-rework]].

**Contrast with:** Jumping straight to `/new-sprint` without validating assumptions.
